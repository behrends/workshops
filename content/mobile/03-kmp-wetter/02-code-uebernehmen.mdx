<DocsOnly>

(`org.jetbrains.androidx…`), nicht direkt von Google. Die Versionen
können deshalb etwas hinter denen für Android liegen.

## Code kopieren

1. `model/`, `data/` und `ui/` (mit `ui/theme`) aus `schritt-10` nach
   `shared/src/commonMain/kotlin/…` kopieren
2. Paketnamen in `package` und Imports ersetzen (`weatherandroidtif24` → `weatherkmptif24`)
3. `App()` zeigt die Wetter-App

```kotlin
@Composable
fun App() {
    WeatherAndroidTIF24Theme {
        WeatherApp()
    }
}
```

<DocsOnly>
Paketnamen und Imports lassen sich in Android Studio auf einmal ersetzen:
*Edit → Find → Replace in Files*. Die Paketnamen hier gelten für ein
Projekt namens `WeatherKMPTIF24` (Paket `com.example.weatherkmptif24`);
bei einem anderen Namen entsprechend anpassen. Den Beispielcode des Templates
(`Greeting`, `Platform`) brauchen wir nicht mehr.

Das Theme heißt weiterhin `WeatherAndroidTIF24Theme`. Wir benennen es
bewusst nicht um, damit die Änderungen in den nächsten Schritten nur das
zeigen, was für KMP nötig ist.

<Callout type="warning">
  Dieser Zwischenstand kompiliert absichtlich nicht. Die Fehler zeigen,
  was nur unter Android oder auf der JVM funktioniert. Fehlerliste:
  `./gradlew :shared:compileKotlinIosSimulatorArm64 --continue`
</Callout>

## Was nicht mehr kompiliert

Alles, was es nur unter Android oder auf der JVM gibt:

| Stelle | Ersatz |
|---|---|
| `HttpClient(OkHttp)` | `HttpClient { … }`, Engine pro Plattform |
| `java.io.IOException` | `kotlinx.io.IOException` |
| `"%.2f".format(…)` | String-Template |
| Dynamic Color im Theme | feste Farben |
| Preview mit `uiMode` | Theme mit `darkTheme = true` |

<DocsOnly>
Die meisten Änderungen sind Einzeiler. Für `IOException` gibt es mit
kotlinx-io einen Ersatz für alle Plattformen; Ktor bringt die Bibliothek
schon mit, es ändert sich nur der Import.

Ohne Engine nimmt Ktor die, die für die Plattform eingebunden ist:

```kotlin
// Ohne Angabe der Engine nimmt Ktor die der Plattform: OkHttp (Android), Darwin (iOS)
val httpClient = HttpClient {
    expectSuccess = true
    install(ContentNegotiation) {
        json(Json { ignoreUnknownKeys = true })
    }
}
```

`String.format` gibt es in Common Kotlin nicht. Die Koordinaten stehen
deshalb ungerundet in der Liste:

```kotlin
Text(text = "${city.latitude}° N, ${city.longitude}° O")
```

Im Theme entfällt Dynamic Color (Farben aus dem Hintergrundbild, ab Android 12):

```kotlin
@Composable
fun WeatherAndroidTIF24Theme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    // Dynamic Color gibt es nur unter Android, deshalb hier feste Farben
    val colorScheme = if (darkTheme) DarkColorScheme else LightColorScheme
    // …
}
```
</DocsOnly>

## Navigation 3 ohne Reflection

```kotlin
private val navConfig = SavedStateConfiguration {
    serializersModule = SerializersModule {
        polymorphic(NavKey::class) {
            subclass(CityList::class, CityList.serializer())
            subclass(CityWeather::class, CityWeather.serializer())
        }
    }
}

val backStack = rememberNavBackStack(navConfig, CityList)
```

<DocsOnly>
Der Back Stack wird gespeichert, damit er Drehen und Prozessende übersteht.
Unter Android findet die Bibliothek per Reflection selbst heraus, welche
Routen es gibt. Unter iOS gibt es keine Reflection, deshalb melden wir
alle Routen ausdrücklich an. Neue Routen müssen hier ergänzt werden.

Zurück geht es unter iOS ohne weiteren Code: `NavDisplay` reagiert auf das
Wischen vom linken Bildschirmrand, so wie es iOS-Apps gewohnt sind.

## Kompiliert, stürzt aber ab

Unter iOS stürzt die App beim Start ab:

```
UnsupportedOperationException: `Factory.create(String, CreationExtras)` is not implemented.
```

```kotlin
// WeatherApp
val weatherViewModel = viewModel { WeatherViewModel() }
// WeatherScreen (Default-Parameter)
viewModel: WeatherViewModel = viewModel { WeatherViewModel() },
```

<DocsOnly>
Auch hier fehlt Reflection: `viewModel()` ohne Parameter erzeugt das
ViewModel unter Android per Reflection. Unter iOS kompiliert der Aufruf
zwar, wirft aber zur Laufzeit eine Exception. Mit dem Initializer
`{ WeatherViewModel() }` steht im Code, wie das ViewModel erzeugt wird.

Dieselbe Änderung steht auch beim Default-Parameter von `WeatherScreen`.
Dort stürzt es nie ab, weil `WeatherApp` das ViewModel immer übergibt;
wir ändern es trotzdem, damit kein `viewModel()` ohne Initializer übrig bleibt.

Wer nur Android testen kann, bemerkt diesen Fehler nicht. Deshalb gehört
zu KMP, regelmäßig auf allen Plattformen zu testen.

- Von gut 600 Zeilen Kotlin ändern sich 6 Dateien mit rund 40 Zeilen
- Composables, ViewModel, Repository, DTOs: unverändert
- Der Grund für fast jede Änderung: Android-APIs und Reflection gibt es auf iOS nicht
