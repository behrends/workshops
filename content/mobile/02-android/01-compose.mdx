# Compose-Grundlagen

<DocsOnly>
Wir bauen die Oberfläche der Wetter-App Schritt für Schritt mit
Jetpack Compose auf. Am Ende dieser Seite zeigt die App das Wetter
einer Stadt mit Fake-Daten an.

Code: [Repository auf GitHub](https://github.com/behrends/WeatherAndroidTIF24),
Schritte 0 bis 4.

Codebeispiele mit `// ...` oder `/* ... */` sind gekürzt; der
vollständige Code steht im Repository unter dem jeweiligen Tag.
</DocsOnly>

## Die Wetter-App

Eine Liste von Städten, nach Antippen das aktuelle Wetter der Stadt.

- Schritte 1–8: Oberfläche und Architektur mit Fake-Daten
- Schritt 9: echte Wetterdaten von Open-Meteo, angebunden mit einem Coding Agent
- Schritt 10: Feinschliff mit Material 3
- Jeder Schritt ist ein Commit mit Tag, z. B. `schritt-05`

<DocsOnly>
Ausgangspunkt (`schritt-00`) ist ein neues Projekt mit der Vorlage
*Empty Activity* und dem Namen `WeatherAndroidTIF24`. Aus dem
Projektnamen erzeugt Android Studio den Namen des Themes
(`WeatherAndroidTIF24Theme`) und des Pakets
(`com.example.weatherandroidtif24`); bei einem anderen Namen heißen sie
entsprechend anders. Wer nicht selbst tippen möchte, klont das
Repository und wechselt mit `git checkout schritt-00` an den Anfang.

In `gradle/libs.versions.toml` markiert Android Studio Versionen gelb,
für die es eine neuere gibt; Alt+Enter setzt sie ein. Das
Referenz-Repository verwendet die Versionen der Vorlage. Aktualisieren
ist möglich, kann aber weitere Anpassungen nötig machen, z. B. eine
neuere Version des Android-Gradle-Plugins.

In `MainActivity` bleibt nur das Nötigste übrig:

```kotlin
setContent {
    WeatherAndroidTIF24Theme {
    }
}
```

`setContent { … }` legt fest, welche Composables die Activity anzeigt.
Die geschweiften Klammern sind ein **Trailing Lambda**: Ist der letzte
Parameter einer Funktion eine Funktion, darf sie hinter den runden
Klammern stehen. `setContent { … }` ist also kurz für
`setContent(content = { … })`. Diese Schreibweise steckt in fast jedem
Compose-Code, z. B. `Column { … }` oder `Scaffold(…) { innerPadding -> … }`.

Zusätzlich liegt im Repository eine Datei `AGENTS.md` mit Regeln für
Coding Agents (siehe [Navigation und API](./04-navigation-api)).

<Callout type="info">
Ohne lokale Installation geht es auch im Browser:
[Google AI Studio](https://ai.google.dev/gemini-api/docs/aistudio-android)
erzeugt aus einem Prompt ein Android-Projekt mit Kotlin, Compose und
ViewModel, wie wir es hier aufbauen. Die App läuft in einem

Übung: die Wetter-App per Prompt erzeugen lassen und mit unserem Code
vergleichen.
</Callout>
</DocsOnly>

## Projektstruktur

Der Kotlin-Code ist nach Aufgaben in Pakete aufgeteilt.

```
app/src/main/java/com/example/weatherandroidtif24/
├── MainActivity.kt
├── ui/          Screens und Composables, ViewModels
│   └── theme/   Farben, Schriften, Theme (aus der Vorlage)
├── model/       Datenmodell: City, CurrentWeather
└── data/        Datenquellen: Fake-Daten, Repositorys
    └── api/     HTTP-Client und DTOs (ab Schritt 9)
```

<DocsOnly>
Pfade auf dieser und den folgenden Seiten (z. B. `ui/WeatherScreen.kt`)
beziehen sich auf diesen Ordner. In der Ansicht *Android* von Android
Studio erscheint er unter `app/kotlin+java/com.example.weatherandroidtif24`.

Neue Pakete und Dateien legen wir per Rechtsklick auf das Paket an:

- *New → Package* für einen Unterordner wie `model`
- *New → Kotlin Class/File* für eine Datei, dann z. B. *File* wählen

`ui/` mit `ui/theme/` bringt die Vorlage *Empty Activity* schon mit;
die übrigen Pakete entstehen in Schritt 3 (`model`, `data`) und
Schritt 9 (`data/api`).

## Composables

Ein Composable ist eine Kotlin-Funktion, die beschreibt, wie ein Teil der Oberfläche aussieht.

<DocsOnly>
Neue Datei `ui/WeatherScreen.kt` im Paket `ui`, das die Vorlage schon mitbringt:
</DocsOnly>

```kotlin
@Composable
fun WeatherScreen(modifier: Modifier = Modifier) {
    Text(text = "Lörrach", modifier = modifier)
    Text(text = "14 °C", modifier = modifier)
}
```

<DocsOnly>
Compose arbeitet **deklarativ**: Wir beschreiben, *was* angezeigt
werden soll, nicht *wie* die Oberfläche Schritt für Schritt verändert
wird. Ändern sich die Daten, ruft Compose die Funktion erneut auf und
zeichnet das Ergebnis neu.

<Callout type="info">
**Ausblick:** Dasselbe Prinzip heißt in Flutter *Widget*, in React Native
*Komponente*. Die Oberfläche entsteht immer als Baum verschachtelter
Bausteine:

| Framework | Baustein | Beispiel |
|---|---|---|
| Compose | Composable | `Column { Text("Lörrach") }` |
| Flutter | Widget | `Column(children: [Text('Lörrach')])` |
| React Native | Komponente | `<View><Text>Lörrach</Text></View>` |
</Callout>

Konventionen für Composables:

- Annotation `@Composable`
- Name in `PascalCase`, wie eine Klasse
- kein Rückgabewert: Composables erzeugen UI, statt etwas zurückzugeben
- ein optionaler Parameter `modifier: Modifier = Modifier`: Standardwert
  ist der leere `Modifier`; so kann der Aufrufer z. B. Abstände von außen
  festlegen. Das Composable gibt ihn an sein äußerstes Element weiter.

Damit `WeatherScreen` auch in der App erscheint, ruft `MainActivity`
es auf:

```kotlin
setContent {
    WeatherAndroidTIF24Theme {
        // Abstand zu Statusleiste und Kamera-Aussparung
        WeatherScreen(modifier = Modifier.safeDrawingPadding())
    }
}
```

Neue Projekte zeichnen *edge-to-edge*, also bis unter die Statusleiste.
`safeDrawingPadding()` hält den Inhalt aus diesen Bereichen heraus.

Die beiden Texte überlappen sich, weil noch ein Layout fehlt. Darum
geht es im nächsten Abschnitt.

<Callout type="info">
**Warum überlappen sich die Texte?** Anders als in HTML ordnet Compose
Elemente nicht automatisch untereinander an. Ohne Layout landen alle
Kinder an derselben Stelle oben links; die Anordnung legt erst ein
Layout wie `Column` fest. Deshalb bekommen hier auch beide `Text`s den
`modifier`: Es gibt noch kein äußerstes Element, an das er gehen könnte.
</Callout>
</DocsOnly>

<SlideBreak />

Mit `@Preview` zeigt Android Studio ein Composable direkt im Editor an, ohne Emulator.

```kotlin
@Preview(showBackground = true)
@Composable
fun WeatherScreenPreview() {
    WeatherScreen()
}
```

<DocsOnly>
Die Preview aktualisiert sich bei jeder Änderung im Code. Für
Interaktionen (Antippen, Eingaben) gibt es den interaktiven Modus der
Preview; für alles andere starten wir die App im Emulator.

## Layouts: Column, Row, Box

Composables werden mit Layout-Composables angeordnet.

- `Column`: untereinander
- `Row`: nebeneinander
- `Box`: übereinander, z. B. Inhalt auf einem Hintergrund
- `Spacer`: Abstand bzw. freier Platz

<SlideBreak />

Die Verschachtelung im Code entspricht der Verschachtelung auf dem Bildschirm.

![Layout als verschachtelte Boxen: Bildschirm und Code haben denselben Aufbau](/images/mobile/android/compose-layout-baum.svg)

<SlideBreak />

```kotlin
Column(horizontalAlignment = Alignment.CenterHorizontally) {
    Text(text = "Lörrach", fontSize = 28.sp)
    Text(text = "⛅", fontSize = 72.sp)
    Text(text = "14 °C", fontSize = 48.sp)
    Spacer(modifier = Modifier.height(16.dp))
    Row(modifier = Modifier.fillMaxWidth()) {
        Text(text = "Wind: 8 km/h")
        Spacer(modifier = Modifier.weight(1f))
        Text(text = "Teilweise bewölkt")
    }
}
```

<DocsOnly>
Dieser Code steckt in einem neuen Composable `CurrentWeatherCard`,
ebenfalls in `ui/WeatherScreen.kt`.
`WeatherScreen` ruft es nur noch auf und reicht seinen `modifier` weiter:

```kotlin
@Composable
fun WeatherScreen(modifier: Modifier = Modifier) {
    CurrentWeatherCard(modifier = modifier)
}
```

`CurrentWeatherCard` legt eine `Box` mit Hintergrund um die `Column`
(siehe nächster Abschnitt zu Modifiern).

Größen werden in `dp` (*density-independent pixels*) angegeben, damit
sie auf allen Displays gleich groß wirken. Schriftgrößen in `sp`
(*scalable pixels*): wie `dp`, berücksichtigen aber zusätzlich die
Schriftgröße aus den Systemeinstellungen.

<Callout type="warning">
Bei Alt+Enter auf den richtigen Import achten: `androidx.compose.ui.Modifier`
(nicht `java.lang.reflect.Modifier`) und `androidx.compose.ui.graphics.Color`
(nicht `android.graphics.Color`).
</Callout>

`Spacer(Modifier.weight(1f))` nimmt den gesamten freien Platz in der
`Row` ein und schiebt so den zweiten Text an den rechten Rand.

Layouts lassen sich beliebig verschachteln. Im Unterschied zu älteren
UI-Systemen ist das in Compose kein Performance-Problem.
</DocsOnly>

## Modifier

Modifier verändern Größe, Abstand, Hintergrund und Verhalten eines Composables.
Sie werden durch aufeinanderfolgende Funktionsaufrufe verkettet.

```kotlin
Box(
    modifier = modifier
        .fillMaxWidth()
        .padding(16.dp)
        .background(Color(0xFFBBDEFB), RoundedCornerShape(24.dp))
        .padding(24.dp),
    contentAlignment = Alignment.Center,
) { /* Column von oben */ }
```

<Callout type="warning">
Die Reihenfolge zählt: `padding` vor `background` ist Außenabstand,
`padding` nach `background` ist Innenabstand.
</Callout>

<DocsOnly>
Die Kette beginnt mit dem Parameter `modifier` statt mit `Modifier`.
So erreicht der Modifier des Aufrufers (z. B. `safeDrawingPadding()`
aus `MainActivity`) das äußerste Element, statt verloren zu gehen.

Am besten in der Preview ausprobieren: die beiden `padding`-Aufrufe
vertauschen oder einen entfernen und den Unterschied ansehen.

Weitere häufige Modifier: `size`, `fillMaxSize`, `clickable`, `border`, `clip`.

## Datenmodell mit data class

Statt fester Texte bekommen Composables nun Daten als Parameter.

```kotlin
data class City(
    val name: String,
    val latitude: Double,
    val longitude: Double,
)

data class CurrentWeather(
    val temperature: Double,
    val windSpeed: Double,
    val condition: WeatherCondition,
)
```

<DocsOnly>
Neue Dateien `model/City.kt` und `model/CurrentWeather.kt` im neuen
Paket `model`.

Eine `data class` bekommt automatisch `equals`, `toString` und `copy`.
Ihre Properties sind mit `val` nur lesbar; Getter erzeugt Kotlin
automatisch, Setter gibt es nur bei `var`.
Für feste Auswahlmöglichkeiten wie die Wetterlage eignet sich eine
`enum class`. Sie steht mit in `model/CurrentWeather.kt`:

```kotlin
enum class WeatherCondition { CLEAR, PARTLY_CLOUDY, CLOUDY, FOG, RAIN, SNOW, THUNDERSTORM }
```

Die Koordinaten in `City` brauchen wir erst in Schritt 9 für die API.
Das Datenmodell ist aber von Anfang an so aufgebaut, dass es später
passt.

Die Fake-Daten liegen in `data/FakeData.kt` im neuen Paket `data`:
eine Liste von Städten und eine `Map`, die Städtenamen das Wetter zuordnet.

```kotlin
val fakeCities: List<City> = listOf(
    City(name = "Lörrach", latitude = 47.6156, longitude = 7.6614),
    // ... Freiburg, Basel
)

val fakeCurrentWeather: Map<String, CurrentWeather> = mapOf(
    "Lörrach" to CurrentWeather(
        temperature = 14.2,
        windSpeed = 8.5,
        condition = WeatherCondition.PARTLY_CLOUDY,
    ),
    // ... Freiburg, Basel
)
```

Vollständig:
[`FakeData.kt`](https://github.com/behrends/WeatherAndroidTIF24/blob/schritt-03/app/src/main/java/com/example/weatherandroidtif24/data/FakeData.kt)
</DocsOnly>

<SlideBreak />

Composables sollten Daten als Parameter erhalten und sie nicht eigenständig holen.

```kotlin
@Composable
fun CurrentWeatherCard(
    city: City,
    weather: CurrentWeather,
    modifier: Modifier = Modifier,
) {
    // ...
    Text(text = city.name)
    Text(text = weather.condition.emoji())
    Text(text = "${weather.temperature.roundToInt()} °C")
}
```

<DocsOnly>
Solche Composables heißen **stateless**: Sie zeigen nur an, was sie
als Parameter bekommen. Dadurch lassen sie sich in der Preview mit
beliebigen Daten testen.

Die Anzeige der Wetterlage ist eine Erweiterungsfunktion mit `when`
in `ui/WeatherConditionUi.kt`. Sie gehört zur UI, nicht ins Datenmodell:

```kotlin
fun WeatherCondition.emoji(): String = when (this) {
    WeatherCondition.CLEAR -> "☀️"
    WeatherCondition.PARTLY_CLOUDY -> "⛅"
    // ...
}
```

`when` muss alle Fälle der `enum class` abdecken. Kommt ein neuer Fall
hinzu, meldet der Compiler jede Stelle, die angepasst werden muss.
Nach demselben Muster liefert `WeatherCondition.label()` den Text
(„Sonnig“, „Regen“ …) für die rechte Seite der `Row`; links steht die
Windgeschwindigkeit `weather.windSpeed`.

Auch `WeatherScreen` bekommt die Daten jetzt als Parameter und reicht
sie an die Karte weiter. Die Preview übergibt Fake-Daten:

```kotlin
@Composable
fun WeatherScreen(city: City, weather: CurrentWeather, modifier: Modifier = Modifier) {
    CurrentWeatherCard(city = city, weather = weather, modifier = modifier)
}

@Preview(showBackground = true)
@Composable
fun WeatherScreenPreview() {
    val city = fakeCities.first()
    WeatherScreen(city = city, weather = fakeCurrentWeather.getValue(city.name))
}
```

Auch `MainActivity` übergibt jetzt die Fake-Daten:

```kotlin
val city = fakeCities.first()
WeatherScreen(
    city = city,
    weather = fakeCurrentWeather.getValue(city.name),
    modifier = Modifier.safeDrawingPadding(),
)
```

## Scaffold und TopAppBar

Compose bringt die Komponenten von **Material Design 3** mit, dem Designsystem von Google. `Scaffold` ist das Grundgerüst eines Screens, z. B. mit einer `TopAppBar`.

```kotlin
Scaffold(
    topBar = { TopAppBar(title = { Text(text = city.name) }) },
) { innerPadding ->
    CurrentWeatherCard(
        city = city,
        weather = weather,
        modifier = Modifier.padding(innerPadding),
    )
}
```

<DocsOnly>
Das `Scaffold` steht in `WeatherScreen`, das dafür
`@OptIn(ExperimentalMaterial3Api::class)` braucht: `TopAppBar` ist noch
als experimentell markiert.

`innerPadding` ist der Platz, den `TopAppBar`, Statusleiste und
Navigationsleiste belegen. Der Inhalt bekommt ihn als Modifier, damit
nichts verdeckt wird. In `MainActivity` entfällt deshalb
`Modifier.safeDrawingPadding()`:

```kotlin
WeatherScreen(city = city, weather = fakeCurrentWeather.getValue(city.name))
```

Die Preview legt das Theme der App (`WeatherAndroidTIF24Theme`) um den
Screen. Sonst zeigt sie die Standardfarben von Material 3, nicht die der
App:

```kotlin
@Preview(showBackground = true)
@Composable
fun WeatherScreenPreview() {
    val city = fakeCities.first()
    WeatherAndroidTIF24Theme {
        WeatherScreen(city = city, weather = fakeCurrentWeather.getValue(city.name))
    }
}
```

Die Karte behält vorerst ihre feste Farbe und Schriftgrößen. Farben und
Schriften aus dem Theme, `Card` und Dark Mode kommen am Ende dazu (siehe
[Material 3](./05-material)).
